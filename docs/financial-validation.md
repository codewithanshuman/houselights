# Financial model validation and known limits

Financial validation is presently **unavailable**: no matched, genuine, prospectively recorded concert settlement has been supplied. The existing historical concert workbook supports an outcomes catalog but not reliable pre-event financial features or complete settlement P&Ls. It cannot calibrate this simulation and is never silently converted to training records.

`GET /api/financial/validation` reports the count of qualifying prospective matched settlements. With zero records it returns `status: no_matched_financial_outcomes`, `count: 0`, null error metrics and `calibrated: false`. `POST /api/financial/outcomes` accepts an organizer-attested settlement reference, real paid-ticket total and signed settled profit only after the event date. It links them to one saved simulation, assumption set and selected lineup. Retrospectively created simulations are excluded from validation. The service checks chronology, capacity and arithmetic of the submitted fields, but cannot authenticate the private source document.

When genuine prospective settlements exist, the endpoint reports actual sample size, mean absolute profit error, bias, mean absolute paid-ticket error, break-even Brier score and empirical 5th–95th scenario-range coverage. These diagnostics do not establish calibration on a tiny or selective sample. A publishable validation claim requires representative events, independently verified settlements, a fixed pre-event model specification, a chronological holdout and reporting of missingness. Qloo/no-Qloo incremental value requires **matched** event cohorts with timestamped pre-event Qloo signals and a no-Qloo baseline; current financial data do not permit that comparison.

Automated tests cover cent reconciliation, tax and fee ownership, zero-demand/capacity boundaries, cancellation terms, fixed-seed replay, invalid correlation matrices, shared risk factors, CVaR reference values, hard-feasible finalists, twin integration, 10,000/100,000-draw performance, private API access and interrupted-worker cancellation. Passing those tests establishes implementation behavior under declared inputs, not predictive validity of the inputs themselves. The public illustration includes explicit synthetic and no-calibration labels.
